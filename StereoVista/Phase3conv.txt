❯ We are migrating StereoVista from OpenGL to Vulkan, one phase at a time. You  
  are                                                                           
  picking up at Phase 3 (Mesh forward PBR + shadow mapping). This is a native   
  Vulkan REWRITE, not a line-by-line port — make it cleaner/faster/idiomatic,   
  and                                                                           
  FIX the OpenGL bugs rather than reproducing them.                             
                                                                                
  BEFORE writing any code, read these two docs in full:                         
    1. docs/VULKAN_MIGRATION_STATUS.md   (READ THIS FIRST — living status,      
  working                                                                       
       rules, per-phase detail, session log)                                    
    2. docs/VULKAN_MIGRATION.md          (design rationale + the "§6b           
  Native-Vulkan                                                                 
       Playbook" of best-practice nudges)                                       
                                                                                
  Then read the actual source you're about to touch — don't trust the docs as   
  ground truth about the code (they lag). Key files: src/Renderer/Renderer.cpp, 
  headers/Renderer/Renderer.h, headers/Renderer/passes/TonemapPass.h (the pass- 
  object pattern to mirror), src/Loaders/ModelLoader.cpp, and the GL reference  
  shaders under assets/shaders/core/ (fragmentShader.glsl, shadowMapping*,      
  simpleDepth*, point-shadow cubemap, skybox).                                  
                                                                                
  START with the restructure, NOT with lighting. See the Phase 3 detail in      
  STATUS §2 — the first "⚠ FIRST restructure the already-ported Renderer"       
  bullet.                                                                       
  Summary: Renderer::recordFrame currently INLINES the whole scene pass and the 
  Renderer has NO scene input (updateViewUniforms fakes a swaying camera and    
  draws                                                                         
  a hardcoded triangle). If you bolt shadow/forward/skybox on as more inline    
  blocks you rebuild the renderEye() monolith this migration exists to kill. So 
  first:                                                                        
    1. Extract ShadowPass / ForwardPass / SkyboxPass as objects mirroring       
       TonemapPass; make recordFrame drive a pass LIST.                         
    2. Give the Renderer a real per-frame scene input (camera matrices + draw   
  list                                                                          
       + lights).                                                               
    3. Delete the Phase 2 demo scaffold (triangle VB/IB, checker texture,       
       materialSampler_, trianglePipeline_, createTriangleScene) as the mesh    
  path                                                                          
       lands.                                                                   
    4. Migrate ViewUniforms (Renderer.h) std140 -> layout(scalar) (playbook     
  A.1).                                                                         
                                                                                
  Then the Phase 3 work itself (STATUS §2 Phase 3 "How" + "→ Nudges"):          
  rhi::Buffer                                                                   
  uploads for Mesh (reuse Assimp import as-is), per-view camera UBO (already    
  multiview-aware — keep it that way, don't bake single-view assumptions),      
  bindless materials via the reflected pipelines + bindingOverride, directional 
  shadow map + point-light depth cubemap, skybox. Design for multiview NOW so   
  Phase 7 stereo stays additive.                                                
                                                                                
  FIX these GL bugs instead of porting them (playbook §C, all verified          
  present):                                                                     
  one metallic-roughness PBR path (delete the Blinn-Phong duplication, C.3);    
  drop                                                                          
  the do-nothing SpotShadowCalculation stub or implement a real spot shadow     
  (C.4);                                                                        
  real per-light attenuation params (C.5); keep the lit pass linear-HDR only —  
  no                                                                            
  tonemap/sRGB (that lives in TonemapPass), sample albedo via sRGB image views  
  (C6); principled normal-offset + slope-scaled shadow bias + one PCF path      
  (C.7);                                                                        
  bindless material struct instead of material.textures[16]/hasTexture-as-float 
  (C.8). The RHI foundation (Device/Swapchain/Buffer/Texture/Pipeline/          
  DescriptorAllocator/Barrier/TonemapPass/frame loop) is sound — build on it,   
  no                                                                            
  RHI rewrite needed.                                                           
                                                                                
  Working rules (from STATUS "READ ME FIRST"):                                  
  - If unsure about a Vulkan API/extension/best pattern, DIG DEEPER: read more  
    source and use the internet (Khronos spec/registry, Vulkan-Samples, vendor  
    docs). Don't guess. For product/scope decisions only the owner can make,    
  ASK.                                                                          
  - Prefer good libraries over hand-rolling (e.g. meshoptimizer, KTX — playbook 
    §D); if you add one, fully self-integrate it (vendor files + .vcxproj +     
    .filters + post-build DLL copy + green build; keep license, avoid GPL) and  
    record it in STATUS §4.                                                     
  - Keep it compiling green (CI on push, or the local Windows/MSVC build). The  
    agent environment can't run the GPU app — the USER verifies each phase      
    visually on their machine. At the phase boundary: get the build green, then 
    give the user concrete run/verify steps and wait for their result.          
  - When you finish, UPDATE docs/VULKAN_MIGRATION_STATUS.md (phase board, Phase 
  3                                                                             
    detail, §4 decisions) and append a short dated Session Log entry.           
                                                                                
  Take your time. Restructure first, then land lighting incrementally.
